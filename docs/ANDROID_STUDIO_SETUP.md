## Cache maintenance

The user script provides an explicit maintenance task only when requested. It does not eagerly resolve configurations during normal sync/build:

```bash
./gradlew -PcarobdCacheWarmup=true carobdWarmAllConfigurations --no-configuration-cache --console=plain
./gradlew --offline -PcarobdCacheWarmup=true carobdWarmAllConfigurations --no-configuration-cache --console=plain
```

Every normal artifact-bearing resolvable configuration, including buildscript classpaths, is checked: debug/release, unit/instrumentation, lint, compiler/plugin and tooling/provider configurations. Internal *DependenciesMetadata buckets are inspected but resolved via their real variant classpaths/BOM, rather than requesting artifacts with intentionally absent standalone versions. Project outputs are generated by tasks and excluded from the external-artifact cache view. Failures are reported with the exact configuration and cause; a failed resolution is not counted as a fully warmed cache. Gradle manages all artifact storage in the persistent user cache. Offline help alone is not proof that all variant dependencies are cached.
